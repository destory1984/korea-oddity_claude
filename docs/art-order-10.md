# 그래픽 발주서 10: 걷기 시험판의 지도 2장과 걷는 유이

명동역을 직접 걸어 다니는 시험판(`docs/walk/`)에 쓸 그림을 주문했다. 사용자의 말(2026.10.12): "아예 YS처럼 만들까", "2번. 명동역 시험판 만들어봐". 옛 16비트 액션 RPG처럼 위에서 내려다본 픽셀 아트다. 특정 게임의 그림을 흉내 내라고 쓰지 않았다.

- 쓴 날: 2026.10.12. 받은 날: 2026.10.12
- 그리는 손: 챗GPT의 그림 그리기. Codex CLI로 넣었다(`tools/art-order.sh`).
- 주문한 것: 3장. 모두 한 번에 받았다.
- 둔 곳: `docs/walk/art/`. 지도는 768×1152의 WebP(품질 88), 유이는 높이 192의 PNG 석 장.

## 1. 주문한 3장

| 파일 | 무엇 | 참고 그림 |
|---|---|---|
| `station` | 명동역 지하 대합실의 지도. 1024×1536(세로) | 배치도 `station-plan.png` |
| `street` | 명동 거리의 지도. 1024×1536(세로) | 배치도 `street-plan.png` |
| `yui-walk` → `yui-down`, `yui-up`, `yui-side` | 유이의 앞모습, 뒷모습, 옆모습. 자홍 바탕의 한 장을 세로로 셋으로 잘랐다 | `yui-j1.png` |

## 2. 배치도를 넣어 지도를 받는 법

지도는 12칸 × 18칸이고 `docs/walk/maps.json` 에 한 글자가 한 칸으로 적혀 있다. 그 글자를 색 네모로 칠한 배치도를 만들어 참고 그림으로 넣고, "배치도의 벽, 바닥, 물건의 자리와 크기를 한 칸도 옮기지 말고 그대로 지켜 그린다"고 썼다. 색마다 무엇을 그릴지를 한 줄씩 적었다(짙은 회색은 벽, 분홍은 가게의 진열대, 파랑은 개찰구, 노란 줄무늬는 출구 계단).

받은 두 장은 배치도와 칸이 맞는다. 주소에 `?grid` 를 붙이면 그림 위에 칸의 색이 겹쳐 보여 눈으로 맞추어 볼 수 있다. 벽 한 칸, 가게 두 칸, 계단 네 칸이 모두 제자리에 왔다.

주문 문장은 `assets/codex/order10/` 의 `_head.txt`, `station.txt`, `street.txt`, `yui.txt` 다. 이 폴더는 커밋하지 않는다.

## 3. 받고 확인한 것

| 확인 | 결과 |
|---|---|
| 지도가 배치도와 맞는가 | 두 장 모두 맞는다 |
| 글자, 숫자, 사람이 없는가 | 없다. 출구의 번호판은 숫자 없는 노란 네모로 왔고, 번호는 게임이 얹는다 |
| 색이 차분한가 | 역은 회색과 베이지다. 거리는 차양의 빨강, 파랑, 노랑이 조금 짙다 |
| 유이가 `yui-j1` 과 같은 아이인가 | 그렇다. 하늘색 겉옷, 꿀빛 단발, 빨간 머리핀과 배낭과 운동화 |
| 옆모습이 오른쪽을 보는가 | **아니다.** 왼쪽을 보고 왔다. 게임이 오른쪽으로 갈 때 뒤집어 쓴다 |
| 걷는 동작이 있는가 | 없다. 선 모습 셋뿐이고, 걸을 때는 게임이 통통 뛰게 한다. 걷는 동작은 시험판이 쓸 만하다고 정해지면 주문한다 |

## 4. 다시 주문하는 법

```bash
bash tools/art-order.sh assets/codex/order10-station assets/codex/order10/station.txt station.png assets/codex/order10/station-plan.png
```
