## 3. 아직 정하지 않은 것

1. **사진 포개기의 손맛.** 시험판을 사용자가 손전화로 만져 보고 답해야 한다. 물을 것은 넷이다. 포개는 일이 재미있는가, 너무 쉽거나 어려운가(지금은 14픽셀 안에서 끌려간다), 반투명 사진이 풍경을 가리지 않는가, 다이얼과 날기의 손가락이 부딪치지 않는가.
2. **절기를 보이는 것.** 기획서에 없던 것을 시험판에 넣어 보았다. 다이얼에는 눈금만 있고 이름은 위쪽 날짜 아래에 보인다. 둘지 뺄지 정한다.
3. **시험판을 손전화로 여는 길.** 저장소가 비공개라 GitHub Pages를 쓸 수 없다(무료 요금제). 공개로 돌리거나, 파일을 손전화로 보내 열거나, 시험판만 다른 공개 저장소에 둔다.
4. **이름표의 네 가지**(`docs/이름표.md` 끝). 조선을 朝鮮王朝로 적는가, 바다 이름(서해, 동해)을 어떻게 적는가, 일본어 읽기를 한국어 소리로 통일하는가, 팔만대장경의 이름.
4. **기획서 15절의 아홉 가지.** 제목, 세 나라 사이의 자리 넷, 번체, 칸 수, 가는 길의 출발점 들이다.
5. **할머니의 답장 글자 수.** 답장은 일본어로 옮기면 25자를 넘는다(2차 시험에서 가장 긴 줄이 33자). 답장만 한도를 따로 둘지 정한다.
6. **일본어, 중국어 손글씨 글꼴.** 시험판은 Yomogi와 Ma Shan Zheng을 임시로 골랐다. 할머니의 연필 글씨로 보이는지 사용자가 보고 정한다.
7. **소라 대사 13번의 새 줄.** "한자는 같은데 소리가 다르네."를 뺐다.
8. **글자 수를 세는 법.** 메모 25자에 띄어쓰기와 날짜를 넣어 세는가. 기획서 6절의 본보기 메모는 넣어 세면 50자가 넘는다. 2권은 화면 메모(25자)와 수첩 메모(60자)로 나누었다.

## 4. 찾아낸 문제

- 카메라 포개기는 진짜 카메라로 시험하지 못했다. 가짜 영상(캔버스)을 넣어 겹치기, 찍기, 붙이기까지는 확인했다. 손전화에서 뒤쪽 카메라가 열리는지, 찍힌 범위가 화면의 틀과 같은지는 사용자가 현장에서 봐야 한다. 카메라는 https 나 localhost 에서만 열린다. 파일로 연 시험판에서는 안 열릴 수 있고, 그때는 "사진첩에서 고르기"만 된다.
- 내 사진의 날짜는 붙인 날이다. 찍은 날이 아니다. 사진첩에서 고른 옛 사진도 오늘 날짜가 찍힌다.

- 다이얼을 세게 튕기면 반년 넘게 굴러간다(2권의 미끄러짐 값 그대로다. 2권은 한 칸이 1년이라 괜찮지만 3권은 한 해가 한 바퀴다). 사용자가 다이얼을 정했으므로 손대지 않았다. 손맛을 보고 말이 나오면 줄인다.
- 받은 그림의 세부(첨성대의 단 수, 무량수전의 생김새)를 사진과 견주지 않았다.

- 해 계산 시험의 기준 값(서울의 하지와 동지, 정동진의 1월 1일 해돋이)은 기억으로 적었다. 계산이 4분 안에서 맞았지만, 한국천문연구원의 값으로 다시 확인해야 한다.
- 부석사 그림이 보는 쪽을 남서(방위 235도)로 잡은 것은 어림이다. 무량수전 앞에서 실제로 어느 쪽 능선이 보이는지 확인해야 한다.

## 6. 일하는 법

- 화면을 그림 파일로 찍을 때는 `tools/shots.ps1` 을 돌린다. 크롬을 머리 없이 띄운다. 시험판 주소 끝에 `#near`, `#shot`, `#settings`, `#hush`, `#journal`, `#list`, `#story`, `#route` 를 붙이면 그 장면에서 시작하고, `?lang=ja` 를 붙이면 그 말로, `?sq=buseoksa` 를 붙이면 그 칸에서 열린다. 윈도우의 크롬은 창 너비를 500픽셀 아래로 줄이지 못한다. 그래서 700픽셀로 찍고 가운데 420픽셀을 잘라 낸다. 머리 없는 크롬은 그림을 쓰고도 끝나지 않을 때가 있어, 스크립트가 그림이 생기면 크롬을 끝낸다. 아래는 한 장만 손으로 찍을 때다.

```bash
chrome --headless=new --hide-scrollbars --allow-file-access-from-files --window-size=700,832 --virtual-time-budget=4000 --screenshot=docs/mock/overlay-3.png "file:///<저장소 경로>/docs/overlay-proto.html#shot"
```

- 눈에 띄는 일을 하나 마치면 `docs/바뀐-것들.md` 의 그날 맨 위에 한 줄을 더하고, 같은 커밋에 넣는다.
- 고친 뒤에는 실제 브라우저에서 눌러 본다. 멈춘 그림만으로는 굴릴 때의 반짝임, 칸 옮기기, 찍히는 것을 확인할 수 없다. 2026.10.7에 로컬 서버로 띄워 다이얼 끌기(반짝임 12개, 바늘의 내려앉음), 끝 딱지 누르기(오늘로 구름), 수첩의 "가기"(첨성대 → 부석사), 끌어서 찍기, 이야기 카드의 문제, 가는 길의 열림, 소리 끄기의 "쉬잇"을 모두 눌러 보았고 오류가 없었다.
- 깃허브에 올리기 전에 매번 사용자에게 묻는다.
