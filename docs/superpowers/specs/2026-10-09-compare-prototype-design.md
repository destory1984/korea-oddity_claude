# 비교 시제품 설계서

- 쓴 날: 2026.10.9
- 바탕: `팔도한량-비교시제품-작업서.md`(사용자가 2026.10.9에 가져온 작업서), 도윤의 초안 `20261009_도윤-팔도한량-새기획서.md`
- 이 문서는 작업서를 이 저장소에서 어떻게 지을지 적은 것이다. 놀이의 규칙은 작업서와 초안이 정하고, 여기서는 그 둘에 없는 것과 고친 것만 정한다.

## 1. 무엇을 왜 짓는가

한 게임 안에 장소 둘을 둔다. 성산일출봉은 A안(다이얼 넷으로 옛 사진과 포개기), 첨성대는 B안(지점 셋 × 때 셋에서 골라 찍고 결과를 읽어 다시 찍기)이다. 여섯 사람이 둘을 이어서 해 보고 어느 쪽을 한 번 더 하고 싶은지로 두 안을 가른다.

다 지은 것으로 보는 기준은 셋이다.

1. 작업서의 시험표 열여섯 줄(성산 8, 첨성대 8)이 통과한다.
2. 너비 375픽셀 화면에서 탑의 잘림, 탑의 가림, 그림자의 유무, 다이얼의 걸림이 구별된다.
3. 로그에서 비교의 숫자 넷(진입에서 첫 성공까지의 시간, 셔터 횟수, 도움 횟수, 성공 뒤 "한 번 더 찍기"를 눌렀는지)이 뽑힌다.

하지 않는 것은 작업서 9절 그대로다. 번역, 100곳, 가는 길, 이야기 카드, 날기와 걷기, 물때와 달, 점수, 실제 사진 가져오기, 외부 전송.

## 2. 사용자가 정한 것 (2026.10.9)

- **그림은 이번에도 발주해서 받는다**("발주해서 받아"). 작업서는 "임시 단색 도형"이라 했지만 코드로 그리지 않는다.
- 디렉토리 이름은 `oddity-korea_claude` 로 바꾸었고 깃허브 저장소 이름은 그대로 둔다("깃헙은 이대로").

## 3. 사용자가 답하지 않아 권고대로 잡은 것

사용자가 "계속해"라고 하여 권고를 따랐다. 바꾸려면 짓기 전에 말한다.

- 있는 첨성대 겹 석 장을 그대로 쓰고 여섯 장만 새로 주문한다(5절).
- 구성은 바닐라 JS와 SVG, DOM이다. 1권은 Vite와 Babylon.js라 작업서의 "다르면 바닐라로"에 해당한다.
- 해 계산은 저장소에 있는 `docs/assets/sun.js`(NOAA의 식, 시험 일곱)를 쓴다. astronomy-engine을 내려받지 않는다.

받으면 `tools/key-sky.py` 로 자홍색을 지우고 `docs/assets/scenes/` 에 WebP로 둔다. 잰 높이와 맨 아래의 색은 `places/*.json` 에 적는다. `seong-field`, `seong-grass` 는 `tools/season-layers.py` 로 철의 그림 넉 장을 만든다. 출처는 `THIRD-PARTY.md` 에 적는다.

먼저 `seong-ridge` 한 장을 받아 보고, 쓸 만하면 나머지 다섯을 한꺼번에 넣는다.

### 코드가 맡는 것

받은 그림을 놓고 색을 입히는 일이다. 지금 시험판과 같은 방식이다.

- 하늘의 색, 해, 별.
- 낮, 저녁, 밤의 빛. 겹에 CSS 필터(밝기와 색조)를 입힌다.
- 네 철. 미리 만든 넉 장을 이웃한 둘끼리 겹쳐 녹인다.
- 지점에 따른 구도. 같은 겹을 키우거나 민다.
- 할머니의 바랜 사진. 같은 겹을 목표 자리에 놓고 바랜 색을 입힌다.

### 품을 같게 두는 법

두 장소 모두 받은 그림 넷(첨성대: 먼 산, 고분, 탑과 풀밭, 나무. 성산: 바다, 능선, 들판, 풀)과 하늘로 짓는다. 첨성대의 "사진에만 있는 아이들" 겹(`cheom-class`)은 쓰지 않는다. 성산의 그림자는 판정의 단서라 넣는다.

## 6. 사진을 저장하는 법

찍은 사진은 그림 파일이 아니라 그때의 상태값이다.

- 성산: `{x, d, s, h, matched}`
- 첨성대: `{spot, time, task, ok}`

결과 화면, 비교, 수첩은 이 값을 `ui/scene.js` 에 넘겨 같은 풍경을 다시 놓는다. 저장이 작고, 붙인 사진과 판정이 어긋나지 않는다. 임시 사진은 장소마다 최근 3장을 두고, 수첩에 붙인 사진은 따로 둔다.

## 7. 저장

localStorage 의 한 키 `paldo.compare.v1` 아래 JSON 하나다.

```json
{
  "version": 1,
  "screen": "journal",
  "place": null,
  "seongsan": {"visited": false, "dials": {"x": -0.4, "d": 0.2, "s": 0.5, "h": 12}, "overlay": false,
               "shots": [], "pasted": null, "memory": false, "firstMatchAt": null},
  "cheomseongdae": {"visited": false, "spot": "A", "time": "day", "task": 1, "help": 0,
                    "shots": [], "pasted": {"photo": null, "1": null, "2": null}, "memory": false, "otherView": false},
  "answer": null,
  "log": []
}
```

- 성산의 처음 값은 구도, 계절, 시각이 모두 틀린 자리다. 첨성대의 `pasted.photo` 는 마지막에 붙인 아무 사진이고 `"1"`, `"2"` 는 그 과제를 채운 사진이다.
- 다이얼을 놓은 직후, 지점이나 때를 바꾼 직후, 셔터를 누른 직후, 수첩에 붙인 직후 저장한다.
- 다시 들어오면 `screen` 과 `place` 로 같은 화면, 같은 상태로 돌아온다.
- 수첩에 붙이기는 사진과 기억 기록을 한 번에 쓴다. 쓰기가 실패하면 성공 연출을 내지 않고 "다시 붙이기"를 보인다.
- 읽은 값이 JSON이 아니거나 `version` 이 다르면 원본을 `paldo.compare.v1.broken` 에 옮겨 두고 "복구" 안내를 띄운다. 스스로 지우지 않는다. 안내에서 "새로 시작"을 고르면 그때 새 저장을 만든다.
- 같은 사진을 두 번 붙여도 기억은 1이고 답장은 한 번 온다.

## 8. 로그

저장 JSON의 `log` 배열에 쌓는다. 한 줄은 `{place, t, kind, value}` 이고 작업서 3절의 표와 같다.

- `dial` 은 다이얼을 놓을 때 한 줄을 쓴다. 굴리는 동안의 값은 쓰지 않는다.
- `shutter` 의 `value` 는 그때의 상태 전체와 판정이다.
- 해 계산이 실패하면 `kind: "fallback"` 한 줄을 쓴다.
- 거리 다이얼을 고정하면(9절) `kind: "config"` 한 줄을 쓴다.

시작 화면의 "로그 내보내기" 단추는 `log` 와 비교의 숫자 넷을 JSON으로 클립보드에 복사한다. 클립보드가 막혀 있으면 글 상자에 띄워 손으로 복사하게 한다. 밖으로 보내지 않는다.

## 9. 성산일출봉 (A안)

작업서 4절대로 짓는다. 거기 없는 것과 고친 것만 적는다.

### 풍경

- 겹 다섯: 하늘(코드), 바다, 능선, 들판, 풀. 패럴랙스 계수는 0, 0.1, 0.3, 0.6, 1.0.
- 좌우(x): 겹을 `x × 계수 × 화면 너비의 30%` 만큼 민다.
- 거리(d): 겹을 `1 + (1 - d) × 계수 × 0.8` 배로 키운다. d가 0이면 풀이 1.8배가 되어 능선을 가린다.
- 계절(s): 들판과 풀의 넉 장을 겹쳐 녹인다. 해 계산의 날짜가 된다.
- 시각(h): 해의 높이와 방위를 `sunAt(33.458, 126.942, 날, h × 60 - 540)` 로 구한다.

### 고친 곳 1: 보는 쪽은 서쪽이다

작업서는 "해가 동쪽에 낮게 떴을 때 찍는 사람의 그림자가 능선 쪽으로 뻗는다"고 한다. 그러려면 사진기는 해를 등지고 서쪽을 보아야 한다. 그래서 보는 쪽을 방위 270도, 화면의 가로를 60도로 둔다.

- 아침 해는 화면 밖(뒤쪽)이라 보이지 않는다. 하늘빛과 그림자로만 아침을 안다.
- 해의 방위가 240 → 300도이고 높이가 0도 위면 해를 화면에 그린다. 저녁에 지는 해가 능선 위로 들어온다.
- 실제 성산의 지형과 맞지 않는다. 일출봉은 뭍의 동쪽 끝이라 뭍에서 보면 동쪽을 본다. `seongsan.json` 에 `"staging": true` 와 그 까닭을 적는다. 초안 5절도 임시 연출이라고 적었다.

### 하늘과 그림자

- 하늘 색은 해의 높이로 네 색을 잇는다. -6도 아래는 밤, 0도는 새벽(오전) 또는 저녁(오후), 10도 위는 낮.
- "해가 낮게 떠 있다"는 높이 -0.83 → 10도다. -0.83도는 해의 윗가장자리가 수평선에 닿는 높이이고, `sun.js` 가 해 뜨는 시각을 셈할 때 쓰는 값이다. 작업서는 0 → 10도라 했지만, 그러면 목표 시각 06:40(높이 -0.2도, 해돋이 06:37)이 밤으로 판정된다.
- 오전과 오후는 방위 180도로 가른다. 작업서의 "60 → 120도"는 한여름과 한겨울에 끝에 걸려서 쓰지 않는다.
- 그림자 겹은 해가 낮게 떠 있고 오전일 때 보인다. 높이가 낮을수록 길다.

### 다이얼

화면 아래에 가로 눈금 다이얼 넷을 쌓는다. 한 줄의 높이는 44픽셀이다. 끌거나 PC에서 휠로 굴린다. 계절 다이얼은 4월, 7월, 10월, 1월의 가운데에서 가볍게 걸리고, 넷을 똑같이 표시한다.

2권의 둥근 유리 다이얼은 한 화면에 넷을 둘 수 없어 쓰지 않는다. 걸림과 눈금 소리만 가져온다.

### 판정

`judgeContinuous` 가 셋을 따로 본다.

| 조건 | 식 |
|---|---|
| 구도 | \|x - 0.3\| ≤ 0.1 이고 \|d - 0.6\| ≤ 0.1 |
| 계절 | 날이 9월 15일 → 11월 15일 |
| 시각 | 해의 높이 -0.83 → 10도이고 방위 180도 아래(오전) |

셋이 다 맞으면 포개짐이다. 틀린 것이 여럿이면 구도, 계절, 시각의 차례로 하나만 짚는다.

### 고친 곳 2: 소라의 말 여섯 줄

작업서의 다섯 줄에 저녁의 한 줄을 더한다. 저녁에는 해가 낮지만 앞에 있어 "해가 너무 높다"가 맞지 않는다. 첨성대와 줄 수도 같아진다.

| 틀린 것 | 가르는 값 | 소라 |
|---|---|---|
| 구도 | 위의 구도 조건 | 산 모양이 사진이랑 달라. |
| 계절 | 위의 계절 조건 | 들판 색이 좀 다르다. |
| 밤 | 해의 높이 -0.83도 아래 | 할머니 사진은 아침인데. |
| 낮 | 해의 높이 10도 위 | 그림자가 없어. 해가 너무 높다. |
| 저녁 | 높이 -0.83 → 10도, 방위 180도 위(오후) | 해가 앞에 있어. 그림자가 뒤로 가. |
| 다 맞음 | | 겹쳤다! 이 그림자, 할머니야? |

### 옛 사진과 포개짐의 알림

- "옛 사진"을 켜면 목표값으로 놓은 풍경에 바랜 색을 입혀 불투명도 0.4로 덮는다. 능선과 그림자의 윤곽선을 함께 그린다.
- 켠 채 포개지면 윤곽선이 풍경과 겹쳐 보인다. 다른 알림은 없다.
- 끈 채 포개지면 다이얼 넷이 0.3초 떨린다.

### 거리 다이얼을 고정하는 길

첫 성공이 6분을 넘기면 다이얼을 셋으로 줄일 수 있게, `seongsan.json` 에 `"fixDistance": false` 를 둔다. `true` 면 d를 0.6에 고정하고 그 다이얼을 숨긴다.

## 10. 첨성대 (B안)

작업서 5절과 초안 4절, 5절, 8절, 9절대로 짓는다. 거기 없는 것만 적는다.

### 구도

| 지점 | 겹을 놓는 법 | 보이는 것 |
|---|---|---|
| A 가까이 | 탑과 풀밭 겹을 2배로 키운다 | 탑의 윗부분이 화면 밖으로 나간다 |
| B 뒤로 | 받은 크기 그대로 | 탑 전체와 넓은 하늘 |
| C 나무 뒤 | B의 구도에 나무 겹을 탑 앞에 놓는다 | 나무가 탑의 절반 넘게 가린다 |

지점을 누르면 0.5초에 걸쳐 옮긴다. 옮기는 동안 셔터가 잠기고, 그동안 다른 지점을 누르면 마지막에 누른 곳으로 간다.

### 때

- 낮: 푸른 하늘, 겹은 받은 색 그대로.
- 저녁: 주황에서 보라로 가는 하늘, 겹은 조금 어둡고 붉게.
- 밤: 남색 하늘과 별, 겹은 어둡고 푸르게.

별은 하늘에만 찍는다. A에서는 탑이 하늘을 거의 다 가려도 별이 보이도록 화면 위쪽 양 끝에 하늘을 남긴다.

### 판정과 소라의 말

`judgeDiscrete` 가 상태의 태그를 과제의 `need` 와 `forbid` 에 대어 본다. 결과에는 필요한 것마다 충족 여부가 따로 들어간다(과제 2의 B-저녁은 탑 충족, 별 미충족).

결과 화면은 필요한 것마다 이름과 표시를 보인다. 이름은 `cheomseongdae.json` 의 `labels`(탑, 풀밭, 별)에서 읽는다. 내부 태그 이름은 보이지 않는다.

소라의 말은 이렇게 고른다.

| 차례 | 조건 | 말 |
|---|---|---|
| 1 | 과제 충족 | `ok1` 또는 `ok2` |
| 2 | 탑끝잘림 | `topCut` |
| 3 | 탑가림이고 과제 2이고 별이 있음 | `starsNoTower` |
| 4 | 탑가림 | `towerHidden` |
| 5 | 탑전체이고 별이 없음 | `noStars` |

이 차례는 `cheomseongdae.json` 의 `soraRules` 에 적고 코드는 그것을 읽는다.

### 도움

누를 때마다 한 단계 오른다. 과제가 바뀌면 0으로 돌아간다. 벌칙이 없다.

1. 단서 강조: 옛 사진에서 필요한 두 요소에 테두리.
2. 그림 설명: 지금 풍경 위에 글 없는 선. A에서는 화면 위 가장자리에 잘린 표시, C에서는 나무에서 탑으로 긋는 선, 과제 2의 낮과 저녁에는 빈 하늘에 점선 별.
3. 해답 미리보기: 성공 상태의 풍경을 흑백으로 작게.

### 수첩의 칸

자리, 사진, 기억 셋은 성산과 같다. 넷째 "다른 시선"은 과제 2를 채운 사진을 붙이면 채워지고, 수첩 칸에 사진 두 장이 나란히 남는다. 과제 1을 붙이기 전에는 과제 2로 넘어가지 않는다.

## 15. 사용자가 해 보고 고치라 한 것 (2026.10.10)

사용자가 손전화로 성산일출봉을 해 보고 한 말 셋이다. 위의 절과 어긋나는 곳은 이 절이 이긴다.

### "들판 색이 다르다는 너무 난감한 얘기야. 좀 더 친절하게"

소라는 눈에 보이는 사실 하나를 구체적으로 짚는다. 첨성대의 "나무가 탑을 가렸어"와 같은 결이다. 성산의 말은 여섯 줄에서 아홉 줄이 되었다.

| 틀린 것 | 소라 | 금빛 테가 도는 다이얼 |
|---|---|---|
| 좌우가 모자람 | 산이 사진보다 오른쪽에 있어. | 좌우 |
| 좌우가 넘침 | 산이 사진보다 왼쪽에 있어. | 좌우 |
| 너무 가까움 | 너무 가까워. 산이 사진보다 커. | 거리 |
| 너무 멂 | 너무 멀어. 산이 사진보다 작아. | 거리 |
| 계절 | 사진 속 들판은 가을빛이야. | 계절 |
| 밤 | 사진은 해 뜰 때야. 지금은 밤. | 시각 |
| 낮 | 그림자가 없어. 해가 너무 높다. | 시각 |
| 저녁 | 해가 앞에 있어. 그림자가 뒤로 가. | 시각 |
| 다 맞음 | 겹쳤다! 이 그림자, 할머니야? | 없음 |

- 좌우와 거리가 둘 다 틀리면 좌우부터 짚는다.
- 소라가 짚은 것을 고칠 다이얼에 금빛 테가 돈다. 그 다이얼에 손을 대면 꺼진다.
- 성산에 처음 들어오면 옛 사진이 2.5초 겹쳐 보였다가 걷힌다. 무엇과 포개야 하는지를 먼저 본다. 첨성대가 과제를 처음 볼 때 옛 사진을 펴 주는 것과 같다.

### "3번 틀리니까 짜증나"

- 틀린 사진을 찍으면 결과 화면으로 가지 않고 그 자리에 머문다. 풍경 위에 소라의 말이 뜨고 바로 고쳐 다시 찍는다. 전에는 틀릴 때마다 결과 화면에 갔다가 "한 번 더 찍기"를 눌러야 했다. 두 장소 모두 같다.
- 틀린 사진도 붙일 수 있게 말풍선 아래에 "이 사진 붙이기"를 둔다. 누르면 결과 화면으로 간다.
- 맞게 찍으면 전처럼 결과 화면으로 간다.
- 잇달아 세 번 틀리면 소라가 도움을 권하고 그 단추가 깜빡인다. 성산은 "옛 사진을 겹쳐 볼까?"(옛 사진 단추), 첨성대는 "도움을 눌러 볼까?"(도움 단추). 누르라고 막지는 않는다. 벌칙도 없다.
- 세는 법: 마지막 성공 뒤로 잇달아 틀린 셔터의 수(`core/log.js` 의 `missStreak`). 첨성대는 과제가 바뀌면 다시 센다.

### "다이얼 좀 더 예쁘게 디자인하고, 돌리는 맛도 넣어줘"

- 생김새: 유리 뒤에서 도는 둥근 통이다. 눈금이 가장자리로 갈수록 촘촘해지고 흐려진다. 유리의 남색(`#0c1442` → `#04061e`)과 금빛 테 두 겹, 윗부분의 윤기는 2권의 유리 다이얼에서 가져왔다. 높이는 44 → 58픽셀이다.
- 눈금 위의 글: 계절은 달 이름(1월 → 12월), 시각은 정각(0시 → 23시), 좌우와 거리는 양 끝(왼쪽과 오른쪽, 가까이와 멀리).
- 바늘은 금빛 줄과 위아래의 세모다. 걸림의 표시는 네 갈래 작은 별 넷이고 똑같이 생겼다.
- 굴리던 힘으로 더 돈다. 놓으면 한 장면(1/60초)마다 빠르기가 0.94배로 줄고, 느려지면 가까운 눈금이나 걸림으로 끌려가 멎는다. 가장 빠르게 튕겨도 25눈금쯤 더 간다.
- 끝이 있는 다이얼(좌우, 거리)은 끝을 넘겨 끌면 뻑뻑해지고 놓으면 되돌아온다.
- 눈금을 넘을 때마다 소리가 나고, 떨림이 되는 기기(안드로이드)에서는 짧게 떤다(3밀리초, 큰 눈금 6, 걸림 12). 아이폰의 브라우저는 떨림을 주지 않는다.

### "이야기"가 와닿지 않는다 → 서사를 넣는다

사용자가 "사진을 이렇게 찍는 이유가 뭐야"라고 물었고, 걸리는 것은 놀이가 아니라 이야기라고 했다("그래서 게임이나 영화는 서사가 중요한거야"). 기획서에 이미 있는 까닭을 시제품이 빼먹고 있었다.

- 할머니는 어느 사진에도 없다. 찍는 사람이라서다. 예외는 1978년 성산일출봉 사진의 긴 그림자 하나다(기획서 5절). 성산에서 사진을 포개는 일은 할머니가 섰던 자리를 찾는 일이다.
- 첨성대의 메모에는 "밤에 별 보러 나가려다 선생님께 들킴"이 있다(기획서 6절). 과제 2의 "탑과 별"은 할머니가 그날 밤 못 본 별을 대신 찍어 드리는 일이다.

넣은 것은 넷이다. 두 장소에 같은 크기로 넣었다.

| 어디 | 무엇 | 글의 출처 |
|---|---|---|
| 시작 화면 | 쪽지 다섯 줄과 소라의 첫 대사 "이번엔 땅이야? 그럼 걸어가도 되겠다." | 기획서 8절의 쪽지, 12절의 1번. "두 군데만 먼저 가 보렴."은 작업서 |
| 장소에 처음 들어갈 때 | 바랜 사진, 그 뒷면의 연필 글씨, 소라의 한마디, "찍으러 가기". 장소마다 한 번 | 첨성대는 기획서 6절의 메모와 12절의 3번 그대로. 성산의 "할머니는 사진에 없어. 늘 찍는 쪽이라."는 새로 지었다 |
| 성산에서 포개진 순간 | 3.6초 머문다. 그림자가 1.6초에 걸쳐 드러나고 소라가 "이 긴 그림자, 할머니야?" 한 뒤 결과 화면으로 간다 | 기획서 12절의 15번 |
| 첨성대 과제 2를 붙였을 때 | 둘째 답장 세 줄 | 새로 지었다. "그날 밤 못 본 별이구나. / 선생님께 들켜서 못 나갔지. / 쉰다섯 해 만에 네가 봐 주었네." |

- 성산의 그림자는 다이얼을 돌리는 동안 보이지 않는다. 포개진 뒤에야 드러난다. 그래서 그림자는 시각을 맞추는 단서가 아니게 되었고, 시각은 하늘빛과 소라의 말로 맞춘다. 할머니의 옛 사진(겹쳐 보기, 결과 화면)에는 그림자가 있다.
- 포개지기 전의 글에서 "그림자"라는 낱말을 뺐다. 화면 메모는 "내가 섰던 자리를 찾아 주련."(새로 지었다), 낮과 저녁의 소라 말은 "해가 너무 높아. 사진은 해 뜰 때야.", "해가 지고 있어. 사진은 해 뜰 때야."다. 시험이 이것을 지킨다.
- 첨성대의 옛 사진(과제 1)에는 수학여행의 아이들이 선다. 발주서 1에서 받아 둔 `cheom-class` 겹이다. 5절의 "쓰지 않는다"를 뒤집었다.
- 할머니의 말 셋(성산의 화면 메모, 첨성대의 둘째 답장)과 소라의 말은 초안이다. 사용자가 고친다.

### "다이얼을 돌리다가, 맞는 위치에 오면, 맞다고 힌트를 줘"

- 다이얼마다 제 값이 맞는 자리에 있으면 초록 테가 돌고 이름표에 "✓ 맞아"가 붙는다. 자리를 벗어나면 바로 꺼진다.
- 막 들어온 순간에는 맑은 두 음이 나고, 떨림이 되는 기기에서는 25밀리초 떤다.
- 맞는 자리는 판정과 같다. 좌우와 거리는 목표 ± 0.1, 계절은 9월 15일 → 11월 15일, 시각은 그 계절의 해가 낮게 뜬 아침이다. 계절을 바꾸면 해 뜨는 때가 달라져 시각의 "맞아"가 꺼질 수 있다.
- 넷이 다 초록이면 포개진 것이다. 셔터는 여전히 사람이 누른다.
- 이로써 성산은 눈으로 포개는 놀이보다 다이얼 넷을 초록으로 만드는 놀이에 가까워졌다. 재미 테스트의 숫자를 읽을 때 셈에 넣는다. 끄려면 `ui/seongsan.js` 의 `dial.good(now)` 한 줄을 뺀다.

### "이것도 다이얼 돌리자", "버튼은 맛이 없어"

- 첨성대의 지점 단추 셋과 때 카드 셋을 다이얼 둘("자리", "때")로 바꾸었다. 값은 여전히 셋씩이고, 다이얼이 세 자리에 걸린다. 한 자리의 너비는 84픽셀이다.
- 다이얼을 돌려 자리가 바뀌는 순간 풍경이 0.5초에 걸쳐 옮겨 가고 그동안 셔터가 잠긴다. 전과 같다.
- 과제 1에서는 "때" 다이얼이 보이지 않는다.
- 첨성대의 다이얼에는 "맞아" 알림이 없다. 결과를 읽고 고치는 것이 이 안의 놀이라서다.

### "다이얼 사진은 좀 고급스럽게... 시간한량이 쓰던 그런 모습으로"

- 다이얼의 생김새를 2권의 유리 다이얼로 바꾸었다. 시험판(`overlay-proto.html`)에 옮겨 둔 2권의 그리는 법을 가져왔다: 별자리판 같은 짙은 남색의 두꺼운 유리, 금빛 테 두 겹과 테에 맺힌 빛, 유리 속에서 함께 도는 북두칠성과 별가루, 굴릴 때 유리 위의 반짝임, 테 위에 박힌 금빛 화살촉(눈금이 지나갈 때 1픽셀 내려앉는다).
- 2권은 화면 아래에 큰 원반 하나를 두지만 여기는 한 화면에 넷이라, 원반의 윗머리만 보이는 높이 68픽셀의 띠로 놓았다. 원반의 반지름은 띠 너비의 1.6배다.
- 값이 맞는 자리에 있으면 테와 화살촉이 초록으로 바뀐다.
- 할머니의 부탁(손글씨 한 줄)은 풍경의 아래쪽에 얹었다. 다이얼이 높아진 만큼 자리를 벌려, 너비 375 × 높이 812 화면에서 성산의 셔터 아래 끝이 656픽셀에 온다.

### "카메라 렌즈 돌리는 것처럼 하자"

바로 앞의 2권 유리 다이얼을 걷고, 다이얼을 카메라 렌즈의 링으로 다시 그렸다. 소라가 사진기를 들고 있으니 이야기와도 맞는다.

- 렌즈 경통을 옆에서 본 모습이다. 링 하나는 높이 60픽셀이고, 위쪽 60%는 눈금과 글이 새겨진 띠, 아래쪽 40%는 손에 잡히는 톱니 띠다. 둘이 함께 돈다.
- 둥근 통이라 가장자리로 갈수록 눈금이 촘촘해지고 글이 옆으로 눌리며 어두워진다. 통의 반지름은 링 너비의 0.62배다.
- 가운데 위의 금빛 세모와 줄은 움직이지 않는 기준선이다. 눈금이 지나갈 때 잠깐 밝아지고, 값이 맞는 자리에 있으면 초록으로 켜진다.
- 링 넷(첨성대는 둘)이 2픽셀 틈으로 붙어 렌즈 하나가 된다. 링의 이름은 왼쪽 위, 지금 값은 오른쪽 위에 경통에 새긴 글처럼 상자 없이 쓴다.
- 색은 시리즈의 남색과 금빛을 지켰다: 검푸른 경통, 흰 새김, 금빛 강조.
- 돌리는 맛: 렌즈의 링은 기름을 먹어 묵직하다. 놓은 뒤 더 도는 힘을 줄였다(한 장면마다 0.94배 → 0.9배. 가장 세게 튕겨도 15눈금쯤). 첨성대의 링은 조리개 링처럼 세 자리에 딸깍 걸린다.
- 2권의 별자리판, 북두칠성, 반짝임은 뺐다.

## 16. 둘째 판: 부석사와 소백산 천문대 (2026.10.10)

사용자가 첫 판의 두 장소를 해 보고 "1은 너무 번거러워.", "딱히 서사가 없다면, 2가 맞겠어."라고 한 뒤 "다른 장소 2개를 A,B안으로 다시 만들어보자"고 했다. 물어서 정한 것은 둘이다.

- 장소: A안은 부석사, B안은 소백산 천문대.
- A안의 조작: 링 둘만(계절, 시각). 자리는 고르지 않는다.

그림은 새로 주문했다("그림은 gpt한테 외주 줘서, 예쁘게 만들어"). 한 장면을 통째로 그린 그림 7장이다(`docs/art-order-3.md`).

### 판

- 주소가 `/compare/` 면 둘째 판(부석사, 소백산)이 열린다. `/compare/?round=1` 이면 첫 판(성산, 첨성대)이 열린다.
- 판마다 저장이 따로다. 첫 판은 `paldo.compare.v1`, 둘째 판은 `paldo.compare.v2`.
- 화면 코드는 장소가 아니라 안에 따라 둘이다. `ui/continuous.js`(A안), `ui/discrete.js`(B안). 장소마다 다른 것은 `places/*.json` 에서 읽는다.

### 부석사 (A안)

- 서사: 1985년 11월 저녁의 사진. 뒷면에 "산이 겹겹이 보였다."(시험판에 있던 메모) 포개지면 소라가 "지붕이 산을 다 가져왔어."(기획서 12절의 12번) 한다.
- 링은 계절과 시각 둘이다. 목표는 11월 6일 17:00이다. 계절은 10월 15일 → 11월 30일, 시각은 해가 낮게 뜬 저녁(11월 6일에는 16:25 → 17:23쯤)이면 맞다.
- 사진기는 남서쪽(방위 235도)을 본다. 가을 저녁의 해는 방위 247도쯤이라 능선 너머 화면 오른쪽으로 진다. 한여름의 해는 방위 296도로 져서 화면 밖이다. 계절을 돌리면 해 지는 자리가 옆으로 옮겨 가는 것이 보인다.
- 그림은 같은 구도의 봄, 여름, 가을, 겨울 넉 장을 겹쳐 녹인다. 하늘의 색, 해, 낮과 밤의 빛, 해 질 녘의 붉은 기운은 코드가 입힌다.
- 소라의 말 다섯 줄: 계절("사진 속 산은 단풍빛이야."), 밤, 낮, 아침, 맞음.

### 소백산 천문대 (B안)

- 서사: 1986년 4월, 핼리 혜성. 뒷면에 "핼리 혜성. 희미했다."(기획서 8절의 쪽지) 지금 하늘에는 혜성이 없다. 과제 2는 혜성이 떴던 자리의 별을 찍는 일이고, 답장이 "다음 2061년 것은 네가 보렴."으로 끝난다.
- 지점 셋: 돔 앞(돔이 사진 밖으로 잘린다), 능선 위(돔과 넓은 하늘), 가로등 밑(불빛에 별이 묻힌다). 때 셋: 저녁, 밤, 새벽.

| 위치 | 저녁 | 밤 | 새벽 |
|---|---|---|---|
| A 돔 앞 | 돔잘림, 노을 | 돔잘림, 별 | 돔잘림, 별 |
| B 능선 위 | 돔, 노을 | 돔, 별 | 돔, 별, 혜성자리 |
| C 가로등 밑 | 돔, 노을 | 돔, 불빛에묻힘 | 돔, 불빛에묻힘 |

| 과제 | 메모 | 필요 | 성공 상태 |
|---|---|---|---|
| 1 | 돔과 별을 함께 담아 주렴. | 돔, 별 | B-밤(때는 밤에 잠겨 있다) |
| 2 | 혜성이 떴던 자리를 담아 주렴. | 돔, 혜성자리 | B-새벽 |

- 소라의 말 여섯 줄: "돔이 사진 밖으로 나갔어.", "가로등이 밝아서 별이 안 보여.", "아직 밝아. 별이 안 떴어.", "그 자리가 아직 산 아래야.", "돔이랑 별이 같이 들어왔다!", "혜성은 없어. 그 자리에 별만 있어."
- 그림은 지점마다 한 장이다. 하늘, 별, 가로등의 불빛, 혜성 자리의 별 다섯, 옛 사진 속의 희미한 혜성은 코드가 그린다.
- 혜성이 떴던 자리와 가로등은 규칙을 시험하려고 지은 연출이다. 1986년의 하늘이나 현장과 견주지 않았다.

- 부석사는 링이 둘뿐이고 "맞아" 알림도 있어 금방 끝난다. 놀이의 품은 소백산보다 작다. 이번 판은 품이 아니라 "서사와 그림이 있을 때 어느 쪽을 한 번 더 하고 싶은가"를 보는 판이다.

## 17. 셋째 판: 성수동 빵집과 홍대 떡볶이 골목 (2026.10.10)

사용자가 둘째 판을 보고 "지금 하고 있는 곳들이 중/일 관광객이 많이 가는 곳인거지?"라고 물었다. 아니었다. 장소를 다시 골랐고 이야기의 틀도 바꾸었다.

- 장소: A안은 성수동 빵집, B안은 홍대 떡볶이 골목. 사용자가 넷 가운데 골랐다.
- 이야기: 맞춰 찍을 사진은 할머니의 옛 사진이 아니라 손녀(소라의 언니)가 요즘 가서 찍어 보낸 사진이다. 할머니는 못 가니 소라가 대신 가서 똑같이 찍어 온다. 답장에서 할머니가 그 자리의 옛날을 말한다.
- 그림은 새로 주문했다. 8장이다(`docs/art-order-4.md`).

### 앞의 판과 달라진 것

| 무엇 | 앞의 판 | 셋째 판 |
|---|---|---|
| 맞춰 찍을 사진 | 할머니의 바랜 사진(세피아) | 언니가 요즘 보낸 사진(바래지 않고 빛깔이 조금 진하다). 자료의 `photo.look` 이 `recent` |
| 단추와 사진 아래의 글 | "옛 사진", "할머니" | "언니 사진", "언니"(`photo.name`, `photo.by`) |
| 시작의 쪽지 | "사진이 다 바랬구나. 네가 새로 찍어다 주련." | "우리 손녀가 다녀와서 사진을 보냈구나. … 네가 대신 가서 똑같이 찍어다 주련." |
| 답장 | 글 석 줄 | 성수동은 글 곁에 같은 건물의 1979년 사진(`replyImage`)이 붙어 온다. 결과 화면과 수첩에 보인다 |
| 계절의 범위 | 한 해 안 | 해를 넘긴다(12월 1일 → 2월 20일) |
| 불빛 | 소백산의 가로등 | 성수동은 창 여섯의 불빛(`glows`), 홍대는 간판의 네온(`neon`) |

### 성수동 빵집 (A안)

- 링 둘(계절, 시각)로 2025년 12월의 눈 온 아침을 찾는다. 목표는 12월 16일 08:00. 계절은 12월 1일 → 2월 20일, 시각은 해의 높이 -0.83 → 10도의 아침이면 포개진다(12월 16일에는 07:45 → 08:45쯤).
- 사진기는 남동쪽(방위 128도)을 본다. 그날 08:00의 해(높이 2.6도, 방위 122도)가 첫째와 둘째 톱날 지붕 사이의 골에 걸린다.
- 창의 불빛은 해가 낮을수록 밝고, 해가 진 밤에는 꺼진다. 소라가 밤에 "빵집도 닫았어"라고 하는 것과 맞추었다.

### 홍대 떡볶이 골목 (B안)

- 자리 셋(가게 코앞, 길 건너, 구경꾼 뒤) × 때 셋(낮, 저녁, 밤), 과제 둘. 과제 1은 가게와 거리를 함께(답: 길 건너의 저녁), 과제 2는 간판에 불 들어온 것(답: 길 건너의 밤).
- 과제 2는 가게 코앞의 밤도 맞는 것으로 했다. 간판의 불과 가게가 다 보이는데 틀렸다고 할 말이 없었다. 초안에서는 이 상태에 소라의 말이 비어 있었다. 시험이 잡았다.
- 네온은 밤에만 켜진다. 자리마다 간판의 자리가 달라 자료에 셋을 적었다.

### 셔터 (사용자, 2026.10.10)

- "카메라 버튼 디자인도 카메라스럽게 다시": 흰 동그라미를 걷고, 톱니를 새긴 검은 테와 금빛 가는 줄 안에 오목한 은빛 단추를 두었다. 누르면 단추가 들어가고 금빛이 번진다. CSS 로만 그렸다.
- "셔터 소리... 반셔터 + 셔터 누르는 소리로 변경", "사진기 소리는 우주 한량한테 얻어와": 1권의 "삐빅 + 찰칵"을 숫자 그대로 옮겼다(`THIRD-PARTY.md`). 처음부터 끝까지 0.71초다.
- "삐빅 + 철컥 + 1초 쉬고 -> 다음 화면으로 전환", 이어서 "1초 -> 2초": B안에서 맞게 찍으면 소리가 끝나고 2초 뒤(누른 뒤 2.7초)에 결과 화면으로 간다. 그동안 다이얼과 셔터가 잠긴다. A안은 맞게 찍으면 전부터 3.6초 머문 뒤에 넘어가므로 그대로 두었다. 틀린 사진은 화면을 옮기지 않는다.

### 가는 길과 거기서 한 일 (사용자, 2026.10.10)

사용자가 셋째 판을 보고 "갔다왔다는게 좀 안 느껴지는데"라고 했다. 수첩에서 "가기"를 누르면 곧바로 그 자리였고, 찍으면 곧바로 수첩이었다. 넣을 수 있는 대목 셋(가는 길, 거기서 한 일, 돌아와서 건네기) 가운데 사용자가 앞의 둘을 골랐다. 돌아와서 건네기는 고르지 않았다.

흐름: 수첩 → 사진과 뒷면 글 → **가는 길** → 그 자리 → 찍기 → **거기서 한 일** → 결과 → 수첩.

- 가는 길(`ui/travel.js`, 자료의 `travel`): 2호선의 초록 줄 위로 점이 달려 역에 멎고(2초), 역 이름과 출구 번호가 뜨며 출구에서 본 골목의 그림이 천천히 다가온다(2초). 소라가 한마디 한다. 처음 갈 때만 다 보이고 다시 갈 때는 그림만 1초 보인다. 화면을 누르면 건너뛴다. 결과 화면에서 "한 번 더 찍기"로 돌아갈 때는 보이지 않는다.
- 성수동은 성수역 3번 출구(앞뒤 역은 뚝섬, 건대입구), 홍대는 홍대입구역 9번 출구(신촌, 합정)다. 출구 번호는 웹 검색으로 보았다(3번 출구가 카페거리 쪽, 9번 출구가 거리 공연이 많은 쪽). 출발하는 곳은 보이지 않는다.
- 거기서 한 일(`ui/there.js`, 자료의 `there`): 장소마다 처음 맞게 찍었을 때, 결과 화면 앞에 먹는 장면이 한 번 나온다. 성수동은 소금빵, 홍대는 떡볶이. "사진 보러 가기"를 눌러야 넘어간다. 수첩의 그 칸에 먹은 것이 작은 딱지로 붙고 표시가 하나 는다.
- 로그: 그 자리에 닿으면 `arrive`, 먹으면 `eat` 줄이 남는다. 첫 성공까지의 시간은 처음 `arrive` 부터 잰다. 가는 길 4초가 섞이지 않는다. 가는 길이 없는 앞의 판은 전처럼 `enter` 부터 잰다.
- 자료에 `travel`, `there` 가 없는 장소(첫 판, 둘째 판)는 전과 같다.
- 그림 4장을 더 받았다(`docs/art-order-4.md` 8절).
